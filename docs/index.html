Directory Reconciliation Agent

Don’t ask an AI if a provider listing is “correct”

Give the model tools, a structured verdict, and a fail-closed confidence floor — not a gut check on messy directory rows.

What the agent does

For each directory record it gathers evidence from authoritative sources (NPI format, NPPES registry, name match, address compare) and returns one of:

  • VERIFIED
  • STALE
  • DEACTIVATED
  • NEEDS_HUMAN_REVIEW
messy directory row
        │
        ▼
agent picks tools as it goes
  · check_npi_format
  · lookup_npi_registry (NPPES)
  · validate_practice_address
  · match_provider_name
  · compare_practice_addresses
        │
        ▼
Verdict {status, confidence, rule_path, evidence}

What “messy” looks like

Same NPI, two cities. An address that was right years ago. A name that almost matches the registry. The identifier can be fine while the location isn’t.

VERIFIED

593 Eddy St, Providence, RI — NPI 1003820432 matches an NPPES practice location.

STALE

45 Wells St, Westerly, RI — same NPI still active; Westerly isn’t in NPPES locations.

NEEDS_HUMAN_REVIEW

Manhasset row — directory name/location disagree with NPPES for NPI 1003582156. Don’t auto-resolve.

Full fixtures: samples/

Confidence, fail closed

Confidence is reported by the model after it sees tool results — LLM-as-judge over evidence, not a weighted score formula in app code. Below a floor of 0.6, policy flips the label to NEEDS_HUMAN_REVIEW.

Offline eval scores a golden set for escalation rate, decisive accuracy, and STALE recall: 

python -m evals.run
